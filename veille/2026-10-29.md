# Veille techno — 2026-10-29

## Ce qui change pour toi
- **Supabase — Data API** — les nouvelles tables du schéma `public` ne sont plus exposées par défaut à l'API, appliqué à tous les projets le 2026-10-30 → toute nouvelle table QResto (migration) devra avoir un `GRANT` explicite + RLS, sinon le client Vanilla JS recevra des erreurs 404/permission.
- **Supabase — TLS** — désactivation d'un sous-ensemble de chiffrements TLS 1.2 sur les APIs HTTP le 10 novembre 2026 → vérifier les vieux clients/tablettes de restaurants (anciens Android/navigateurs) qui scannent le QR.
- **Node.js — release sécurité du 21/10** — 10 CVE corrigées, dont CVE-2026-111497 (décodeur Brotli, RCE) et 2 contournements de vérification d'hôte TLS (v26.12.1, v24.22.1, v22.23.4) → mettre à jour l'API d'El Falek (Express/Prisma) ; Node 20 et 25 sont EOL, à migrer si utilisés.
- **Next.js — release sécurité 16.3.7 / 15.5.27** (9 vulnérabilités, fin septembre) → à appliquer seulement si un projet Next sur Vercel est utilisé (pas le cas de QResto en Vanilla JS).

## À surveiller
- Supabase Pipelines (alpha) : réplication Postgres vers BigQuery/ClickHouse/Snowflake, utile plus tard pour l'analytique multi-restaurants de QResto.
- Marché QR ordering : peu de nouveautés 2026 trouvées (Choice QR, Servingoo) ; rien d'actionnable.

## Action immédiate
- Avant le 30/10 : relire les migrations/tables QResto et ajouter les `GRANT` nécessaires pour les futures tables du schéma `public`. Mettre à jour Node (patchs listés ci-dessus) sur El Falek.
