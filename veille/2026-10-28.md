# Veille techno — 2026-10-28

## Ce qui change pour toi
- **Node.js (CVE)** — Release de sécurité du 21/10 : 10 CVE corrigées, dont CVE-2026-111497 (écriture hors limites dans le décodeur Brotli, RCE possible, sévérité « high », déclenchable via `fetch()` et la décompression auto d'Express 5) + 2 contournements de vérif. hostname TLS. Versions corrigées : v26.12.1, v24.22.1, v22.23.4 → mets à jour l'API d'**El Falek** (Express/Prisma) et vérifie la version Node sur Vercel/Render ; Node 20 et 25 sont EOL, donc pas de correctif.
- **Supabase (Data API)** — Le 30/10/2026, les nouvelles tables du schéma `public` ne sont plus exposées automatiquement à la Data API sur tous les projets → pour **QResto**, toute nouvelle table (migration future) devra avoir un `GRANT`/exposition explicite + policies RLS, sinon le front Vanilla JS aura des 404/403.
- **Supabase (TLS)** — Désactivation d'un sous-ensemble de chiffrements TLS 1.2 sur les APIs HTTP des projets le 10/11/2026 → vérifie que les clients anciens (vieux Android/webviews des téléphones clients au restaurant) se connectent encore ; les navigateurs récents ne sont pas concernés.
- **Next.js** — Cycle de sécurité régulier avec préavis (release du 30/09 : 16.3.7 et 15.5.27, 9 vulnérabilités) → aucun impact direct (QResto est en Vanilla JS), mais à appliquer si un projet Next/Vercel est ajouté.

## À surveiller
- Supabase Pipelines (streaming Postgres vers BigQuery/ClickHouse/Snowflake, alpha publique) et tokens d'accès personnels à portée limitée, utiles pour les stats multi-restaurants de QResto et pour la CI.
- Marché QR ordering : pas d'actu 2026 concrète trouvée cette semaine (résultats anciens uniquement).

## Action immédiate
- Mettre à jour Node vers v22.23.4 / v24.22.1 / v26.12.1 (El Falek et tout script/outil local).
- Avant le 30/10 : vérifier que les tables QResto existantes et futures ont leurs droits/RLS explicites.
